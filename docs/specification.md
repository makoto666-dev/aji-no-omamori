## 1. プロジェクト概要

### 1.1 プロダクト名

**味のおまもり** [確定]

### 1.2 コンセプト

「一つの家庭料理を一枚に残すカード型プロダクト。」[確定]

家庭の味と、その料理にまつわる思い出・作り方・家族の声を次の世代へ「継ぐ」ためのプロダクト。実物の料理カードとWebアプリを組み合わせ、手に取れる記録と、映像・音声で振り返る体験を両立する。[確定]

### 1.3 Webアプリの役割

- 実物のカードに載せたQRコードから、その料理のデジタル記録を開く。[確定]
- 料理の写真、材料、作り方、家族からのメッセージを閲覧できる。[確定]
- 作り方の動画、音声メッセージを再生できる。[仮：実際に用意する素材は要確認]
- 複数の料理をコレクション一覧から見返せる。[確定]

### 1.4 今回の開発範囲

展示で来場者がスマートフォンから体験できる**閲覧中心のMVP**を制作する。[確定]

**今回の対象**：料理詳細画面、コレクション一覧画面、料理ごとのURL、動画・音声の再生、スマートフォン表示、公開・QRコード動作確認。

**今回の対象外**：ログイン、利用者によるレシピ投稿・編集、データベース、決済、通知。[仮]

### 1.5 成功条件

- [ ] 実物のカードのQRコードを読み取ると、対応する料理の詳細ページが開く。
- [ ] 料理詳細からコレクション一覧に移動できる。
- [ ] コレクションから別の料理を開ける。
- [ ] 料理の情報とメッセージが読める。
- [ ] 用意した動画・音声がスマートフォンで再生できる。
- [ ] 展示会場で第三者が説明なしに基本操作できる。

## 2. 想定ユーザー・利用シーン

### 2.1 主なターゲット

- 実家を離れて暮らす大学生・社会人。[確定]
- 家族の味を残したい親・祖父母など。[仮：記録する側として想定]

### 2.2 ユーザーニーズ

- 懐かしい家庭料理を思い出したい。
- 家族が作っていた味を自分でも再現したい。
- 料理の背景にある言葉や思い出を残したい。

### 2.3 主な利用シーン

1. 離れて暮らす人が実物の料理カードを手に取る。
2. カードに印刷されたQRコードをスマートフォンで読み取る。
3. 料理の写真や家族のメッセージを見る。
4. 材料・手順・動画を確認して料理を作る。
5. コレクション一覧から他の料理も見返す。

### 2.4 展示会での利用シーン

来場者が展示されたカードのQRコードを読み取り、サンプルの料理ページを体験する。[仮]

| F-06 | 音声再生 | 家族の音声メッセージを再生 | 推奨 | 仮 |

### 3.1 料理詳細画面の表示項目

- 料理名
- メイン写真
- 家族からのメッセージ
- 材料と分量
- 作り方（番号付きの手順）
- 動画プレーヤー（素材がある場合）
- 音声プレーヤー（素材がある場合）
- 「コレクションを見る」リンク／ボタン

**[要検討]** 調理時間、何人分、作った人の呼び名、料理の思い出、コツなどを追加するか。

### 3.2 コレクション一覧の表示項目

- ページタイトル「味のおまもり」
- コンセプトを伝える短い文章
- 料理カードの一覧（写真・料理名など）
- カードを押すと詳細画面へ移動

**[要検討]** 一覧の並び順、カードの枚数、分類や検索の必要性。

### 3.3 動画・音声の扱い

- [仮] 動画・音声はユーザー操作で再生開始する（自動再生しない）。
- [仮] 動画・音声の素材がない料理ではプレーヤーを表示しない。
- [要検討] 動画の撮影方向、長さ、容量、字幕の有無。
- [要検討] 家族の実際の声を使用する場合、公開への同意を得る。

## 5. 画面遷移・URL・QRコード仕様

### 5.1 遷移フロー

```text
実物の料理カード
   └─ QRコードを読み取る
         └─ 料理詳細（例：肉じゃが）
                ├─ レシピ・動画・音声を見る
                └─ コレクション一覧へ
                       ├─ 肉じゃが詳細
                       ├─ 卵焼き詳細
                       └─ お味噌汁詳細
```

### 5.2 URL設計

- コレクション一覧：`https://<公開ドメイン>/`
- 料理詳細：`https://<公開ドメイン>/?id=<料理ID>`
- サンプルID：`nikujaga`、`tamagoyaki`、`misoshiru` [仮]
- IDは半角英数字・ハイフンなどのURLで扱いやすい形式にする。[仮]

### 5.3 QRコード

- 料理カードごとに、対応する**公開済みの詳細ページURL**をQRコード化する。[確定]
- 印刷前に、実際のスマートフォンで読み取れるか確認する。
- [仮] QRコードはカード裏面に配置する。
- [要検討] 印刷サイズ、余白、背景とのコントラスト、カードのデザインへの組み込み方。
- **注意**：ローカルURL（`localhost` や `127.0.0.1`）をQRコードにしない。
- **注意**：本番URLが確定するまでは最終印刷を行わない。

## 6. データ設計

### 6.1 データ管理方針

展示用MVPでは、料理データをJavaScriptオブジェクトまたはJSONで静的に管理する。[仮]

### 6.2 料理データの項目

| フィールド | 型 | 内容 | 必須 |
|---|---|---|---|
| `id` | string | URLで使う一意のID | ○ |
| `title` | string | 料理名 | ○ |
| `image` | string | 写真のパス | ○ |
| `message` | string | 家族からのメッセージ | ○ |
| `servings` | string | 何人分か | 任意 |
| `ingredients` | array | 材料と分量 | ○ |
| `steps` | array | 調理手順 | ○ |
| `video` | string | 動画のパス | 任意 |
| `audio` | string | 音声のパス | 任意 |
| `author` | string | 料理を継ぐ相手の呼び名 | 任意 |

### 6.3 データ例（仮データ）

```javascript
const recipes = [
  {
    id: "nikujaga",
    title: "肉じゃが",
    image: "assets/images/nikujaga.jpg",
    message: "寒い日に、よく作ってくれた味。",
    author: "お母さん",
    servings: "2人分",
    ingredients: [
      { name: "じゃがいも", amount: "2個" },
      { name: "にんじん", amount: "1/2本" }
    ],
    steps: [
      "野菜を食べやすい大きさに切る。",
      "具材を炒め、煮汁を加えて煮込む。"
    ],
    video: "assets/videos/nikujaga.mp4",
    audio: "assets/audio/nikujaga.mp3"
  }
];
```

> この例の材料・手順・メッセージはダミー。実際のレシピと素材に置き換えること。

### 6.4 初期登録する料理

- 肉じゃが [仮]
- 卵焼き [仮]
- お味噌汁 [仮]

**[要検討]** 展示で実際に使う料理の種類と枚数。

## 7. UI/UX・デザイン仕様

### 7.1 デザインコンセプト

**温かみのある和風・ナチュラル** [確定]

実物のカードやお守り袋と世界観をそろえ、落ち着いた色、柔らかな余白、読みやすい文字組みで、思い出を大切に扱う雰囲気を表現する。

### 7.2 カラーパレット（仮）

| 用途 | 色 | HEX |
|---|---|---|
| 背景 | 生成り | `#F8F4EB` |
| アクセント | くすんだ朱色 | `#A95643` |
| サブアクセント | 深緑 | `#526B57` |
| 本文 | 焦茶 | `#4A382D` |
| 境界・装飾 | 薄茶 | `#E9DDC9` |

### 7.3 文字・余白（仮）

- 日本語を読みやすく表示できるフォントを使用する。
- 本文はスマートフォンで原則16px前後を目安にする。
- 料理名・メッセージ・手順に明確な情報の優先順位をつける。
- タップ対象は押しやすいサイズと間隔を確保する。
- 写真とテキストが密集しないように余白を設ける。

### 7.4 UX原則

- QRコードから**直接その料理**に到達できる。
- 料理の思い出と実用的なレシピの両方が見つけやすい。
- 初めて訪れた人でも、一覧に戻る方法がわかる。
- 動画・音声の再生ボタンと状態がわかりやすい。
- 実物の料理カードとWeb画面で名称・写真・配色を可能な限り統一する。

### 7.5 レスポンシブ対応

- スマートフォンを最優先で設計する（モバイルファースト）。[確定]
- PCでもレイアウトが崩れないようにする。[仮]
- [要検討] 対応する最小画面幅、一覧の列数、写真の縦横比。

| 対応端末 | スマートフォン中心、PCでも閲覧可能 | 仮 |

## 15. 制作メモ

- **今回の目的**は「展示で体験できる完成品を作ること」。投稿機能や認証は後回しにする。
- **体験の中心**は実物のカード。Webアプリは、そのカードだけでは伝えきれない記憶や作り方を補完する。
- **迷ったら**「QRを読む → 料理を見る → 思い出に触れる → 他の料理を見る」が迷わずできるかで判断する。
